# Pokémon TCG AI Battle Challenge: Strategy & Architecture Report

## Executive Summary

Our approach to the Kaggle Pokémon TCG AI Battle Challenge breaks away from attempting to solve the entire game space. Traditional heuristic bots suffer from combinatorial explosion when playing complex decks, and pure deep-RL bots often timeout under Kaggle’s strict 600s inference limit or crash due to illegal actions. 

We solved this by developing a hybrid architecture: a highly consistent **Snorlax/Lopunny Control Deck** piloted by a PyTorch-trained **PPO Agent**. To survive the Kaggle environment, we decoupled training from inference—training locally via PyTorch but deploying a custom **Pure-NumPy Inference Pipeline** augmented by a **Zero-Crash Heuristic Fallback System**.

---

## 1. Deck Selection Strategy: The Control Pivot

Early testing on the `cabt` engine revealed a crucial insight: RL agents struggle to pilot aggressive, multi-stage attacking decks (like Dragapult ex or Roaring Moon ex) due to the multi-turn planning required to execute complex combos.

Instead of fighting the RL's natural tendency to stall, we leaned into it by selecting a **Snorlax/Lopunny Control Strategy**. 
- **Goal:** Lock the opponent's Active Pokémon, deny resources, survive, and win by deck-out.
- **Simplification:** This massively reduces the action space. The agent doesn't need to calculate complex damage math; it just needs to prioritize survival, healing, and trapping the opponent.

By minimizing dead hands and forcing long games (often exceeding 100+ turns), the control deck allows the RL agent to out-survive aggressive heuristic bots that run out of resources.

---

## 2. State Representation & Opponent Modeling

The `cabt` engine outputs deeply nested, imperfect-information JSON observations. Passing this raw data to a neural network is inefficient and leads to overfitting on specific Card IDs. 

We built a custom `ObservationEncoder` that squashes the game state into a highly compressed **24-dimensional Float32 vector**:
1. **Global State (4 dims):** Current turn, step, and remaining prizes.
2. **Self State (10 dims):** Active HP/MaxHP, bench size, attached energy, hand size, deck size, and discard size.
3. **Opponent State (10 dims):** Visible active HP, visible bench size, discard tracking, and an **Estimated Hand Size** generated by our probabilistic Opponent Model.

This extreme compression forces the Actor-Critic MLP (24 → 128 → 128 → 150) to learn abstract concepts like "board advantage" rather than memorizing card interactions.

To prevent sparse-reward stagnation in 100-turn games, we utilized dense reward shaping: `+0.1` per prize card, `+1.0` for a win, `-1.0` for a loss, and a `-0.5` catastrophic penalty for benching out.

---

## 3. Training Methodology: 50/50 Hybrid Curriculum

Training a robust RL agent requires diverse opponents. We trained our PPO agent locally using 9 asynchronous parallel environments, utilizing a **Hybrid Matchmaking Curriculum**:

- **50% Self-Play Checkpoint Pool:** The agent plays against historical snapshots of itself. This prevents strategy collapse and ensures it learns fundamental mechanics (shadowboxing).
- **50% Heuristic Meta Gatekeeper:** We built a "True Sight" rule-based bot capable of piloting 24 highly-optimized Tier-1 meta decks. 
- **Prioritized Sampling:** As training progressed (reaching over 40,000 episodes), the curriculum dynamically increased the frequency of matchups against decks the RL agent was losing to (e.g., Dragapult ex, Roaring Moon ex). This forced the agent to adapt its stalling techniques, successfully turning 20% win rates into 80% win rates against top meta threats.

## 4. Deployment Architecture: Pure-NumPy & Safety Fallbacks

The Kaggle simulation environment operates under a strict 10-minute total time budget and penalizes any runtime exception with an automatic loss.

**Overcoming the PyTorch Overhead:**
Importing PyTorch in the Kaggle container causes a 3-5 second cold start, and maintaining the graph risks memory fragmentation over 100-turn games. We solved this by exporting our trained PyTorch weights to `.npz` arrays. Our Kaggle entrypoint (`policy_agent`) implements a **Pure-NumPy Forward Pass**:
```python
x = np.maximum(0, state @ w['s1_w'].T + w['s1_b']) # ReLU Layer 1
x = np.maximum(0, x @ w['s2_w'].T + w['s2_b'])     # ReLU Layer 2
logits = x @ w['a_w'].T + w['a_b']                 # Actor Head
```

**Action Masking & Zero-Crash Fallback:**
Because the `cabt` engine presents a variable-length list of legal moves every turn, the agent outputs 150 logits. We map the valid actions to these logits, apply a mask of `-1e9` to all illegal actions, and take the `argmax`. 

Finally, the entire inference block is wrapped in an aggressive `try/except` failsafe. If the NumPy inference fails, or if the environment presents a weird Turn 0 state, the agent gracefully falls back to a dummy heuristic that reads the engine's `minCount` and returns the first legal action, guaranteeing a **0% crash rate**.
